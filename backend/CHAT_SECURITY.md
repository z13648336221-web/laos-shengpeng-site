# 聊天接口安全加固文档

## 概述

本次升级对聊天接口进行了全面的安全加固，解决了原有的速率限制缺失、敏感词过滤缺失、访客 ID 验证缺失等安全问题。

## 安全问题分析

### 原有安全问题
1. **无速率限制**: `/api/chat/user` 接口无认证、无限速，可被滥用刷屏
2. **无敏感词过滤**: 用户可以发送任何内容，包括垃圾信息、恶意内容
3. **无访客 ID 验证**: 访客 ID 可以是任意字符串，存在安全风险
4. **无滥用检测**: 同一访客可以无限发送消息，干扰正常客服工作

## 安全加固措施

### 1. 速率限制

**实现**: `backend/server.js`

- **配置**: 基于 IP 的速率限制
- **限制规则**: 每个IP每分钟最多5条消息
- **限制范围**: 所有 `/api/chat/*` 接口
- **特点**: 
  - 1分钟时间窗口
  - 成功请求也计入限制
  - 返回友好的错误消息

**配置代码**:
```javascript
const chatLimiter = rateLimit({
  windowMs: 1 * 60 * 1000, // 1分钟窗口
  max: 5,                   // 每个IP每分钟最多5条消息
  message: { success: false, message: '消息发送过于频繁，请稍后再试' },
  standardHeaders: true,
  legacyHeaders: false,
  skipSuccessfulRequests: false // 成功的请求也计入限制
});
```

### 2. 敏感词过滤

**实现**: `backend/utils/content-filter.js`

- **功能**: 检测和过滤敏感词汇、垃圾信息、恶意内容
- **敏感词分类**:
  - 政治敏感词
  - 违法词汇（毒品、赌博、诈骗等）
  - 广告和营销词
  - 色情词汇
  - 垃圾信息特征
  - 恶意脚本

- **垃圾信息检测**:
  - 连续重复字符
  - 过多的特殊字符
  - 电话号码模式
  - QQ号/微信号模式
  - 邮箱模式
  - 文本长度异常

**测试结果**:
```
✓ 正常咨询业务: 通过
✗ 贷款广告: 拒绝
✗ 毒品相关: 拒绝
✗ 赌博信息: 拒绝
✗ 联系方式: 拒绝
✗ 恶意脚本: 拒绝
```

### 3. 访客 ID 验证

**实现**: `backend/utils/visitor-validator.js`

- **功能**: 验证访客 ID 的有效性和安全性
- **验证规则**:
  - 长度限制: 8-64个字符
  - 字符限制: 只允许字母、数字、连字符和下划线
  - 黑名单检查: 拒绝保留词汇（admin, root, system等）
  - 危险模式检测: 拒绝路径遍历、脚本注入等
  - 时间戳验证: 可选的时间戳过期检查

- **安全 ID 生成**:
  - 格式: `visitor_{timestamp}_{random}`
  - 使用加密安全的随机数生成器
  - 确保唯一性和不可预测性

**测试结果**:
```
✓ visitor_abc123: 有效
✗ admin: 无效 (保留词汇)
✗ ../etc/passwd: 无效 (路径遍历)
✗ <script>: 无效 (非法字符)
✗ ab: 无效 (过短)
```

### 4. 滥用检测

**实现**: `backend/utils/visitor-validator.js`

- **功能**: 检测访客 ID 的滥用行为
- **检测规则**:
  - 1小时内发送超过20条消息
  - 1天内发送超过100条消息
- **响应**: 返回429状态码和友好的错误消息

### 5. 综合安全流程

**消息发送流程**:
```
用户发送消息
    ↓
速率限制检查 (IP级别)
    ↓
访客 ID 标准化
    ↓
访客 ID 格式验证
    ↓
访客 ID 滥用检测
    ↓
内容安全检查 (敏感词 + 垃圾信息)
    ↓
存储消息到数据库
    ↓
触发自动回复 (如适用)
```

## 故障排除

### 问题1: 正常消息被拒绝
**可能原因**:
- 消息包含误判的敏感词
- 访客 ID 格式不符合要求
- 达到速率限制

**解决方案**:
- 检查消息内容是否包含敏感词
- 检查访客 ID 格式是否正确
- 等待速率限制重置

### 问题2: 访客 ID 验证失败
**可能原因**:
- 访客 ID 包含非法字符
- 访客 ID 长度不符合要求
- 访客 ID 在黑名单中

**解决方案**:
- 使用系统生成的访客 ID
- 检查访客 ID 格式
- 避免使用保留词汇

### 问题3: 速率限制过于严格
**可能原因**:
- 限制规则设置过严
- 网络环境导致IP相同

**解决方案**:
- 调整速率限制参数
- 考虑基于用户ID而非IP的限制
